# F25 — Channels each business connects itself

Status: **Built** (first version, 2026-11-09). Decision: D-159.

Settings → **Channels**: each business connects its own WhatsApp number and Facebook Page, and their
messages reach that business's inbox (F24). Replaces "one number / one Page for one business, set in the
server's environment" (F12/F23 POC), which still works as a fallback ("connected through the system
settings").

## Scope

- **Screen** (Settings → Channels): a row per channel with its status (connected · number/Page name,
  connected through the system settings, or not connected). Everyone sees the status; only the owner
  (`business.update`) connects or disconnects (with a confirmation).
- **Facebook**: "Connect Facebook" → Facebook Login (`/dialog/oauth`, signed `state`, 15 minutes) → back to
  `/api/v1/integrations/facebook/callback` → the person's Pages wait (sealed, `oauth_pending`, 15 minutes)
  → they pick one → the Page is subscribed to the app's webhook (`messages`) and its Page token stored.
  Disconnect unsubscribes the Page and removes the connection.
- **WhatsApp**: a short form — Meta's _Phone number ID_ and an access token — checked against the Graph
  API before saving. One-click Embedded Signup replaces the form once LeadFlow is a Meta Tech Provider.
- **Storage**: `channel_connections` (business, channel, Meta id, display name, token sealed with
  AES-256-GCM — `lib/secret-box`, key `CHANNEL_SECRETS_KEY` or derived from `FORM_TOKEN_SECRET`). A number
  or Page belongs to one business; a business has one of each channel. Tokens never reach the browser or
  the logs (the callback's `code`/`state` are masked in logs too).
- **Routing**: webhooks pass the number (`phone_number_id`) or Page (`recipient.id`) a message was sent
  to; `ChannelRegistry` finds the business that connected it (else the environment's), and sends with
  that business's token. Unknown numbers and Pages are ignored.
- **Meta API** behind `integrations/meta` (`cloud` / `memory`), per CLAUDE.md rule 8.

## Meta setup (LeadFlow, once)

- `META_APP_ID` on the server; in the app's Facebook Login (for Business) settings, add
  `<APP_URL>/api/v1/integrations/facebook/callback` as a valid OAuth redirect URI. With Facebook Login
  for Business, create a configuration (Page permissions) and set `META_LOGIN_CONFIG_ID`.
- The app's Messenger webhook (callback URL + verify token) is set once; each connected Page is
  subscribed automatically.
- Until App Review, only people with a role in the Meta app can connect Pages and message them.

## Acceptance criteria

1. The owner connects WhatsApp with a Phone number ID and token; Meta is asked first; the token is stored
   sealed and never returned; the row shows "Connected · <number>".
2. "Connect Facebook" goes to Facebook's sign-in and back; the owner picks a Page; it's subscribed and
   shows "Connected · <Page>"; a sign-in can't be reused; a forged or expired state goes nowhere.
3. Messages to a connected number or Page land in that business's inbox and replies go out with its
   token; unknown numbers or Pages are ignored; the environment's connection keeps working.
4. A number or Page can't be connected to two businesses (409, Hebrew message).
5. Disconnect (with confirmation) stops new messages; existing conversations stay.
6. Managers and employees see the status only; outsiders 404 (route walker); Hebrew and English.
