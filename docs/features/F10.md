## User story and value

As a business owner or employee, I write down what I need to do and when — "call Ron tomorrow at 9" — and LeadFlow reminds me, so no inquiry falls through the cracks.

## What was built

- Tasks: title, notes, due time, assignee (defaults to the creator), optional lead link, reminder on/off, status open/done.
- Tasks page: quick add (due defaults to tomorrow 09:00), grouped overdue (red) / today / upcoming, completed list on demand, tick to complete (optimistic), delete; managers switch between "mine" and the whole team.
- Lead page: the lead's open tasks and quick add; "task added" and "task done" appear in the lead history.
- Dashboard: "my tasks for today" with an overdue count.
- Email reminder to the assignee when a task is due, in the business time zone; sent once (atomic claim), skipped for removed members, muted tasks and tasks more than 24 h overdue; a new due time re-arms it (D-057, D-058).
- Permissions: owners/managers see and assign all; employees see/manage only their tasks and can link only to leads they see.
- API: `GET/POST /tasks`, `PATCH/DELETE /tasks/:id` (tenant scope; walker covers them).

## Acceptance criteria

- [x] A task includes title, assignee, due time, status and an optional lead link; overdue is clearly marked (PRD §19.6) — web tests + e2e.
- [x] The assignee gets a reminder email when the task is due — API tests (once-only, time zone) + e2e through the real background job and Mailpit.
- [x] Employees only see their own tasks — API tests.
- [x] Task events appear in the lead history — API + e2e.

## Verification

- API: `tasks.test.ts` (create/list/order, lead link + history, filters, employee rules, foreign assignee/lead, reminders: once-only, skips, re-arm, time zone), `reminders.test.ts` (regression for the startup crash).
- Web: `tasks.test.tsx` (grouping, quick add ISO due, optimistic tick, manager scope, lead page tasks, dashboard, helpers).
- E2E: `e2e/tasks.spec.ts` (lead → overdue → done → history; real reminder email).

## Found during the build

- The reminder job crashed the real server on start (hook added after `listen`) — fixed (D-059), regression test added.
- Two "אחראי" fields on the lead page were ambiguous for screen readers — the task one is now "אחראי למשימה".
- When every task was done, the page showed no message — now "אין משימות פתוחות / כל המשימות בוצעו".
