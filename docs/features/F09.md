## User story and value

As an owner, I invite my staff by email with the right role, so they can handle leads in LeadFlow with only the access they need.

## What was built

- Team page (owner): invite by email + role (manager/employee), pending invitations with resend and cancel, change a member's role, remove a member with confirmation. Managers see the team read-only; employees get a no-permission state (D-049).
- Invitation email (Hebrew) with a 7-day single-use link; re-inviting replaces the old link; max 50 pending (D-050).
- `/invite` page: who invited you, to which business, which role. Signed out → register (email pre-filled) or log in, then back to the invite (PRD §19.1: no new business). Signed in with another email → explained, with "switch account". Signed in correctly → join → business home; joining verifies the email.
- Removing disables the membership immediately; leads and history are kept; re-inviting reactivates (D-052). The owner can't be demoted or removed.
- API: tenant `GET/POST /invitations`, `POST /invitations/:id/resend`, `DELETE /invitations/:id`, `PATCH/DELETE /members/:userId`; public `POST /invitations/preview` and `POST /invitations/accept` (token in body, D-051; rate-limited). All audited.

## Acceptance criteria

- [x] An owner invites an employee who registers from the email link and joins with the employee role — `team.test.ts`, `e2e/team.spec.ts`.
- [x] The invitation only works for the invited email and only once — API tests (wrong account 403, reuse 400, revoked/expired states).
- [x] Only the owner manages the team; the owner can't be demoted or removed — API and web tests.
- [x] A removed member loses access immediately — API test (404 on the business).
- [x] New employees see only leads assigned to them — e2e (empty until the owner assigns one).

## Verification

- API: `team.test.ts` (8 cases incl. no tokens in logs); the tenant walker covers the new routes.
- Web: `team.test.tsx` (invite, 409 inline, role change, remove with confirmation, resend/cancel, manager read-only, invite page in all states).
- E2E: `e2e/team.spec.ts` — full flow with a real email in Mailpit, on desktop and mobile.
