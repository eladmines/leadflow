## User story and value

As a business user, I get a clear, consistent Hebrew workspace where I can find every section
on desktop and phone, and I can see what to set up next.

## Scope

- Layout with a right-side sidebar (desktop) and a drawer (mobile). Nav order per doc 03:
  Dashboard → My site → Customers & leads → Conversations → Tasks → Appointments → Quotes →
  Automations → Reports → Team → Settings & billing.
- Business switcher (URL-scoped `/b/:businessId/...`), user menu with logout.
- Unverified-email banner (from F01).
- Dashboard: greeting, setup checklist that reflects real state only (profile done, email
  verified; site, form and WhatsApp shown as "next steps").
- "Coming soon" empty states for sections not built yet; loading, error and no-permission states.
- Settings → business details form (reuses F02 fields; OWNER only). Team → members list (F02 API).

## Exclusions

Metrics and cards with numbers (no fake data until F08/F20), global search (after CRM),
notifications centre.

## Database / API

None new; uses F01 and F02 endpoints.

## Tests

Component tests for the nav (active item, `aria-current`), the switcher, the checklist states,
and no-permission rendering; e2e at 375px for the drawer and keyboard navigation.

## Acceptance criteria

- [x] Every nav item is reachable by keyboard; focus is trapped in the open mobile drawer and returns on close (`e2e/shell.spec.ts`).
- [x] No horizontal overflow at 375px; no physical left/right CSS in the codebase (e2e + grep: 0 matches).
- [x] The checklist shows only true states; no placeholder numbers (`shell.test.tsx › dashboard`).
- [x] Switching business changes all data; unknown business ids show a Hebrew "not found" (`shell.test.tsx`, `onboarding.test.tsx`, `e2e/onboarding.spec.ts`).
