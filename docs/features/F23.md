# F23 — Facebook Messenger → leads

Status: **Built** (first version, 2026-11-08). Decision: D-157.

A message to the business's Facebook Page becomes a lead, like WhatsApp (F12): new senders wait to be
classified, business senders get a lead with source "Facebook", and the team replies from the lead page.

## Scope (first version)

- **Meta Messenger Platform**, in the same Meta app as WhatsApp. One Facebook Page connected to one
  business through environment variables, like the WhatsApp POC (no connection screen yet):
  `MESSENGER_PAGE_ID`, `MESSENGER_PAGE_ACCESS_TOKEN`, `MESSENGER_BUSINESS_ID`; the app secret and verify
  token are shared with WhatsApp (same Meta app).
- **Webhook** `GET/POST /api/v1/integrations/messenger/webhook` (`object: "page"`), signed like WhatsApp
  (`X-Hub-Signature-256`, raw body), Meta retries ignored by message id (`mid`).
- **Data**: the WhatsApp tables become channel-aware instead of a second copy — `channel`
  (`whatsapp` | `messenger`) on numbers and messages; for Messenger the "number" is the sender's
  page-scoped id (PSID). Inbox, classification (business / personal), lead thread, notifications and the
  lead list preview work for both channels and show the channel.
- **Leads**: new source `facebook` ("פייסבוק"); the contact's name comes from the sender's Facebook
  profile (Graph API, `first_name last_name`), else "Facebook user". No phone or email (the team can add
  them).
- **Replies** from the lead page through the Send API (`messaging_type: RESPONSE`), within 24 hours of the
  customer's last message — same rule and Hebrew explanation as WhatsApp.
- **Adapters**: `local` (records sends; development and tests) and `cloud` (Graph API), behind
  `apps/api/src/integrations/messenger` (CLAUDE.md rule 8).
- Not in this version: automatic reply / booking on Messenger, Instagram DMs, Facebook Lead Ads,
  attachments (shown as a label), a connection screen, several Pages.

## Meta setup (owner)

- A Facebook Page for the business, added to the Meta app (Messenger → settings → add Page, generate a
  Page access token).
- Webhook for the Page: callback URL above, the same verify token; subscribe the `messages` field.
- Permissions `pages_messaging`, `pages_show_list`, `pages_manage_metadata`. While the app is in
  development mode only people with a role in the app (admins, testers) can message the Page through it;
  real customers need Meta **App Review** (screencast + explanation, days to weeks).
- Free: the Messenger API has no message fees.

## Acceptance criteria

1. A signed Messenger event from a new sender waits in "שיחות" (channel shown), with name and message;
   no contact or lead yet.
2. Marking it business creates a contact (Facebook name) and a lead with source "Facebook" from the
   waiting messages; later messages join that lead.
3. Marking it personal deletes the messages and ignores the sender from then on (undoable).
4. Unsigned or wrongly signed events are rejected (401) and store nothing; the same `mid` twice stores one
   message.
5. A reply from the lead page within 24 hours is sent to the sender and appears in the thread; after 24
   hours the API refuses with a Hebrew explanation.
6. Owners/managers get a notification for a new sender and for messages on their leads (like WhatsApp).
7. Tenant isolation and permissions as WhatsApp: outsiders 404 (route walker), employees only assigned
   leads, only owners/managers see the inbox. No tokens, message texts or PSIDs in logs.
8. Lead source filter, export and reports include "Facebook". Hebrew and English copy.

## Effort

About 2 days: data migration (channel), webhook + adapter, inbox/thread/lead changes, tests and e2e.
