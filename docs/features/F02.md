## User story and value

As a new owner, I set up my business in a short wizard and can leave and come back without
losing anything (AC-01). As a platform, every piece of business data belongs to exactly one
tenant, and no one can reach another business's data (AC-05).

## Scope

- Create a business (the creator becomes OWNER); list my businesses; get and update details.
- A four-step wizard with server-side draft: (1) name + industry, (2) phone + address,
  (3) service areas, (4) opening hours. Optional fields can be skipped. Completing it sets the status to ACTIVE.
- Tenant plugin, `TenantContext`, permission matrix, `requirePermission`.
- Members list (read-only) to prove RBAC; audit events for business create and update.
- Cross-tenant route walker test (covers all future tenant routes).

## Exclusions

Logo upload (F05), invites and role changes (F09), subscription and plan (F13), social links
(optional field, can be added in the wizard later), deleting a business (F14).

## Database changes

- `businesses`: id, name, industry, phone (E.164), address, service_areas (text[]),
  opening_hours (jsonb, validated), timezone (default Asia/Jerusalem), status
  (ONBOARDING/ACTIVE/SUSPENDED), onboarding_step, timestamps.
- `memberships`: id, user_id, business_id, role (OWNER/MANAGER/EMPLOYEE), status, invited_at,
  timestamps; unique(user_id, business_id).

## API contracts (draft)

| Method | Path                                                 | Permission      | Notes                                      |
| ------ | ---------------------------------------------------- | --------------- | ------------------------------------------ |
| GET    | `/api/v1/businesses`                                 | authenticated   | Only my memberships                        |
| POST   | `/api/v1/businesses`                                 | authenticated   | name, industry → 201; caller becomes OWNER |
| GET    | `/api/v1/businesses/:businessId`                     | business.view   | 404 if not a member                        |
| PATCH  | `/api/v1/businesses/:businessId`                     | business.update | Partial details + onboardingStep           |
| POST   | `/api/v1/businesses/:businessId/onboarding/complete` | business.update | Validates required fields → ACTIVE         |
| GET    | `/api/v1/businesses/:businessId/members`             | members.view    | Names, roles, no secrets                   |

Proposed matrix (D-008): business.view = all roles; business.update = OWNER;
members.view = OWNER, MANAGER.

## Backend tasks

Prisma models + migration · tenant plugin + scope registration · permission helper ·
business/membership repositories (ctx-scoped) · service + routes · audit · Israeli phone
normalisation + opening-hours validation (shared) · seed with two businesses · tests.

## Frontend tasks

Post-login routing (no business → wizard; onboarding → resume step; active → dashboard) ·
wizard with progress, back, skip and saved-draft indicator · opening-hours editor (Sun–Sat,
toggle + from/to, sensible defaults) · service-area chips input · phone in `dir="ltr"` ·
component tests.

## Tests

- Route walker: a member of B gets 404 on every tenant route of A (auto-enumerated).
- `businessId` in the body is ignored; EMPLOYEE gets 403 on PATCH; a non-member gets 404, not 403.
- Wizard resume: leave at step 3, log in again, return to step 3 with the data intact.
- Phone normalisation (050-1234567, +972501234567, 972-50-...); invalid hours (from ≥ to).

## Acceptance criteria

- [ ] Register → wizard → dashboard works in the browser, desktop and mobile.
- [ ] Leaving mid-wizard and returning resumes at the saved step (AC-01).
- [ ] User B can't view, change or list business A's data via UI or API (AC-05).
- [ ] An employee can't update business details (AC-10, partial).
