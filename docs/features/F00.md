## Goal and value

Give every later feature a working skeleton, a test harness and shared rules, so agents can
work in parallel without stepping on each other. No end-user value on its own.

## Scope

- pnpm monorepo: `apps/api`, `apps/web`, `packages/shared`; TypeScript, ESLint and Prettier.
- docker-compose: Postgres 16 (`localhost:5432`), Mailpit (`localhost:8025`).
- API: `buildApp()` factory, Zod env config (fails fast), pino logging with redaction and request
  ids, shared error shape with Hebrew messages, `/health` and `/health/db`.
- Prisma with a baseline migration; test helpers (`createTestApp`, `resetDb`) against `leadflow_test`.
- Web: Vite, Tailwind with RTL tokens, Heebo, base UI kit (Button, Field, Card, Alert, Spinner,
  EmptyState), `apiFetch` client, foundation status page, Hebrew 404.
- Playwright (desktop + mobile), GitHub Actions CI.
- Planning artifacts: CLAUDE.md, ARCHITECTURE, DECISIONS, ROADMAP, FEATURE_BACKLOG, feature cards, agents.

## Exclusions

Any domain model or logic: auth, business, sites, leads.

## API contracts

| Method | Path          | Response                                                            |
| ------ | ------------- | ------------------------------------------------------------------- |
| GET    | `/health`     | `200 { status: "ok" }`                                              |
| GET    | `/health/db`  | `200 { status: "ok" }` or `503 { status: "unavailable" }`           |
| any    | unknown route | `404 { error: { code: "NOT_FOUND", message (Hebrew), requestId } }` |

## Tests

- shared: every error code has a Hebrew default; the error body schema.
- api: env fails fast; health ok; DB-down returns 503; 404 shape and Hebrew message.
- web: Field labels and `aria-describedby`; apiFetch headers, error mapping, network failure.
- e2e: `dir="rtl"`/`lang="he"`, healthy backend shown, Hebrew 404, no horizontal overflow at 375px.
