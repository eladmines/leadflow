## User story and value

As an owner, I upload my logo and gallery images so that my site looks like my business.

## Scope

`StorageProvider` interface + S3-compatible adapter (D-011; MinIO in docker-compose locally,
R2 in production) · `assets` table · presigned upload URL with a short expiry and size/MIME
limits · confirm-upload step that verifies the object and records it · image compression and
resizing · business-prefixed keys `businesses/{businessId}/assets/{assetId}` · per-business
storage usage counter (for future quotas) · asset picker in the builder and the logo field in settings.

## Exclusions

Video, documents, malware scanning beyond type/size checks, orphan cleanup job (later task).

## Database changes

`assets` (business_id, object_key unique, mime, size_bytes, width, height, uploaded_by, status
PENDING/READY, created_at).

## API contracts (draft)

`POST /businesses/:id/assets/uploads` → { assetId, uploadUrl, expiresAt } ·
`POST /businesses/:id/assets/:assetId/complete` · `GET /businesses/:id/assets` · `DELETE /businesses/:id/assets/:assetId`.

## Tests

Wrong MIME or oversize rejected (Hebrew error); presigned URL scoped to one key; B can't
complete, list or reference A's asset; tenant walker; the adapter tested against MinIO.

## Acceptance criteria

- [ ] Logo and gallery images upload from the builder and show in preview.
- [ ] Large or unsupported files are rejected with a clear Hebrew message.
- [ ] Another business can't read, list or reference these assets.
