## User story and value

As an owner, I upload my logo and gallery images so that my site looks like my business.

## Scope

`StorageProvider` interface + S3-compatible adapter (D-011; MinIO in docker-compose locally,
R2 in production) · `assets` table · presigned upload URL with a short expiry and size/MIME
limits · confirm-upload step that verifies the object and records it · image compression and
resizing · business-prefixed keys `businesses/{businessId}/assets/{assetId}` · per-business
storage usage counter (for future quotas) · asset picker in the builder and the logo field in settings.

## Exclusions

Video, documents, malware scanning beyond type/size checks, orphan cleanup job (later task).

## Database changes

`assets` (business_id, object_key unique, mime, size_bytes, width, height, uploaded_by, status
PENDING/READY, created_at).

## API contracts (draft)

`POST /businesses/:id/assets/uploads` → { assetId, uploadUrl, expiresAt } ·
`POST /businesses/:id/assets/:assetId/complete` · `GET /businesses/:id/assets` · `DELETE /businesses/:id/assets/:assetId`.

## Tests

Wrong MIME or oversize rejected (Hebrew error); presigned URL scoped to one key; B can't
complete, list or reference A's asset; tenant walker; the adapter tested against MinIO.

## What was built (MVP)

- Upload through the API (multipart, 1 file, ≤ 8 MB); `sharp` fully decodes and re-encodes to WebP ≤ 1920 px with metadata stripped (D-053, D-054). Fake images, SVGs and GIFs are rejected with Hebrew messages.
- `StorageProvider` interface with a local-disk adapter (path-traversal-safe keys); R2 adapter at deployment.
- `assets` table; library API (`GET/POST /assets`, `DELETE /assets/:id`) with a per-business quota (D-056); deleting an image used by the draft or the live site is refused.
- Serving at `/media/<key>` from the API (admin preview via the Vite proxy) and from every public site host (D-055).
- Site: logo (theme), hero background image, about image with alt text, new gallery section with captions as alt text; drafts saved before F05 stay valid (defaults). Renderer escapes URLs and skips images it can't resolve.
- Editor: image library dialog (upload with browser-side checks, pick, delete, usage bar), image fields, gallery editor; live preview shows the images.
- Deferred: logo in the onboarding wizard, orphan cleanup job, cropping/focal point, video.

## Acceptance criteria

- [x] Logo and gallery images upload from the builder and show in preview — web tests, `e2e/media.spec.ts`.
- [x] Large or unsupported files are rejected with a clear Hebrew message — API (text-as-jpg, SVG, GIF, 9 MB) and web (browser-side) tests.
- [x] Another business can't read, list or reference these assets — tenant walker on `/assets`, foreign-asset draft rejected (400).
- [x] Published sites load the images from their own origin — `media.test.ts` (public server) and e2e (naturalWidth checks).
