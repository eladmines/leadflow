## User story and value

As an owner or employee, I see all leads, move them through my pipeline, add notes and the next
action, and know who handles what, so every inquiry gets followed up.

## Scope

- Leads list: search (name/phone/email), filters (stage, owner, source, date), sort, pagination.
- Kanban board by stage, with drag between columns **and** a keyboard/menu alternative.
- Lead card: contact details, source, stage, owner, priority, requested service, value from quotes
  (D-207/D-208/D-210), next action = nearest open task (D-209), tags, notes, activity history (every stage change logged).
- Manual lead creation; duplicate warning by phone or email (no automatic merge).
- Assign an owner. EMPLOYEE sees only leads assigned to them (PRD §20); MANAGER and OWNER see all.
- Empty state guiding to "connect a form" or "add a lead" (PRD §19.3).

## Exclusions

CSV import and duplicate merging (later CRM feature), tasks (F10), custom pipelines editor
(stages fixed to defaults in the MVP unless decided otherwise), export (F14).

## Database changes

Builds on F07 tables; adds `lead_notes` (or notes as activities), indexes for search/filter
(business_id, stage_id), (business_id, owner_id), (business_id, phone_e164).

Permissions: leads.view.all (OWNER, MANAGER), leads.view.assigned (EMPLOYEE), leads.update, leads.assign.

## What was built (MVP)

- Pipeline board (default view): a column per stage with count and value total; native drag-and-drop plus a stage menu on every card; optimistic moves with rollback (D-048).
- List view with search (name, email, phone in any format) and filters (stage, owner incl. "unassigned", source); view and filters live in the URL.
- Lead page: contact (tap-to-call/email), source, stage, owner, value from quotes (won / open, D-207), next action = nearest open task (D-209), custom fields saved with one Save button, tasks/appointments/quotes as cards with only conversation and notes & history as tabs (D-209), notes, and a full history (created, stage changes, assignments, field edits, notes) with who and when.
- Manual lead dialog: validation (name + phone or email), duplicate warning, stage and owner; a matching contact is reused (D-047).
- Permissions: owners/managers see and assign everything; employees see, create and update only their own leads (D-046); other leads → 404.
- API: `GET/POST /leads`, `GET/PATCH /leads/:id`, `POST /leads/:id/notes`, `GET /pipeline`, `GET /contacts/duplicates`; stages and owners validated inside the business; all inside the tenant scope (walker covers them).
- Deferred: CSV import, merging duplicates, tags/priority, custom pipeline editor (D-045), tasks (F10).

## D-207 – D-210 change list (value from quotes, next action = nearest task, lead page in cards)

**Contract** (frozen in `packages/shared/src/leads.ts`; D-207, D-208, D-209, D-210):

- `Lead.expectedValue` and `Lead.nextActionAt` are gone from every lead response (list item, detail, single lead).
- `value: { won: number; open: number }` (whole shekels, ≥ 0, read-only). Quote `totals.total` (agorot, after discount, incl. VAT), rounded half-up once per lead (`agorotToShekels`).
  - `won` = Σ of **all** `ACCEPTED` quotes.
  - `open` (D-210) = the total of the lead's **latest sent quote** only: greatest `sent_at` among its quotes that were ever sent (`sent_at IS NOT NULL`; ties → higher `number`), counted only while it is still `SENT` and not expired (`valid_until` null or ≥ today in the business time zone, same rule as `quotes/service.py::_is_expired`). If that latest sent quote was accepted, rejected or expired, `open` = 0 even if an older sent quote is still `SENT`. Drafts never count.
  - Aggregates use `leadValueForStageKind`: OPEN stage → `open`, WON → `won`, LOST → 0 (won-stage leads add nothing to open value, D-210 §3).
- `nextTask: { id, title, dueAt, assignee: { id, name } } | null` (read-only, `leadNextTaskSchema`): among tasks with `lead_id` = the lead and status `OPEN`, the earliest `due_at` (overdue included, so the most overdue first; ties → `created_at`, then `id`). **Only tasks the member may see**: everyone's for `tasks.view.all` (owner, manager), only `assignee_id = ctx.user_id` for employees. Overdue = `dueAt` < now (client-side).
- Requests: `createLeadRequestSchema` / `updateLeadRequestSchema` have no `expectedValue` and no `nextActionAt`; the import row has no `value`. Old keys are stripped/ignored (no 400). No list filter or sort on next action exists in the shared query schema (none to remove).
- CSV export: drop "ערך משוער (₪)" and "טיפול הבא"; add nothing.
- The lead page's one "שמירה" covers only `customFields` (one PATCH, unchanged endpoint).
- No migration: `leads.expected_value` and `leads.next_action_at` (and its index) stay, unused.
