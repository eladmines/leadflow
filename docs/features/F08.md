## User story and value

As an owner or employee, I see all leads, move them through my pipeline, add notes and the next
action, and know who handles what, so every inquiry gets followed up.

## Scope

- Leads list: search (name/phone/email), filters (stage, owner, source, date), sort, pagination.
- Kanban board by stage, with drag between columns **and** a keyboard/menu alternative.
- Lead card: contact details, source, stage, owner, priority, requested service, expected value,
  next action date, tags, notes, activity history (every stage change logged).
- Manual lead creation; duplicate warning by phone or email (no automatic merge).
- Assign an owner. EMPLOYEE sees only leads assigned to them (PRD §20); MANAGER and OWNER see all.
- Empty state guiding to "connect a form" or "add a lead" (PRD §19.3).

## Exclusions

CSV import and duplicate merging (later CRM feature), tasks (F10), custom pipelines editor
(stages fixed to defaults in the MVP unless decided otherwise), export (F14).

## Database changes

Builds on F07 tables; adds `lead_notes` (or notes as activities), indexes for search/filter
(business_id, stage_id), (business_id, owner_id), (business_id, phone_e164).

## API contracts (draft)

`GET /businesses/:id/leads` (query filters) · `POST /businesses/:id/leads` ·
`GET/PATCH /businesses/:id/leads/:leadId` · `POST /businesses/:id/leads/:leadId/stage` ·
`POST /businesses/:id/leads/:leadId/notes` · `GET /businesses/:id/leads/:leadId/activities` ·
`GET /businesses/:id/pipeline` · `GET /businesses/:id/contacts/:contactId`.
Permissions: leads.view.all (OWNER, MANAGER), leads.view.assigned (EMPLOYEE), leads.update, leads.assign.

## Tests

EMPLOYEE can't list or open unassigned leads (AC-10); a stage change writes an activity; a
duplicate phone gives a warning, not an error; filters and search; tenant walker; Kanban keyboard
move; **core-journey e2e** (see ROADMAP).

## Acceptance criteria

- [ ] An employee receives a lead, adds a note, changes the stage and sets the next action (PRD §15).
- [ ] An employee can't see leads not assigned to them (AC-10).
- [ ] Every stage change appears in the lead's history.
- [ ] Core-journey e2e passes: register → onboard → build → publish → submit → lead in CRM; a second tenant can't see it.
