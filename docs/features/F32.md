# F32 — What visitors do on the website (counts only)

Status: **Built** (first version, 2026-11-23). Decision: D-191 (Accepted).

F31 counts visits. F32 adds what they do, so an owner can see where visitors are lost: which pages
work, which landing pages turn into inquiries, whether people tap the phone or WhatsApp, how far they
scroll, how many start a form and how many send it. **Counts only**: no visitor id, no cookie, no path
of one person through the site, no recordings.

## What the script reports (`apps/api/src/modules/embed/script.ts`)

Small batches to `POST /api/v1/embed/event` (a text/plain body, so no CORS preflight; `sendBeacon` when
the page may be left):

| Kind      | Label                                   | When                                              |
| --------- | --------------------------------------- | ------------------------------------------------- |
| `page`    | the path (no query, no trailing slash)  | every page view                                   |
| `landing` | the path                                | the first page of a browser session               |
| `device`  | `mobile` (<768px) `tablet` `desktop`    | the first page of a browser session               |
| `click`   | `phone` `whatsapp` `email`              | a tap on a `tel:`, WhatsApp or `mailto:` link     |
| `scroll`  | `50` or `90`                            | once, when leaving the page, if that far was seen |
| `form`    | `start`                                 | the first field touched in a form SimpleCatch binds |
| `cta`     | the name the owner gave (max 40 chars)  | a click on a button the owner chose to count      |

A page that fits the screen counts as seen to the end. Sent forms are not an event: they are the
website leads.

## SimpleCatch's own sites (D-192)

The server counts, from the request alone: `page` (every non-prefetch, non-bot view), `landing` (an
entry from outside the site) and `device` (from the user agent). On top of that, each published page
carries **one first-party script** (`site-script.ts`, a narrow exception to D-040): served from the
site's own address, CSP `script-src 'self'; connect-src 'self'` (the rest stays `default-src 'none'`),
no cookies, no storage, no visitor id. It reports to `POST /__sc` (under a path: `/s/<name>/__sc`):
taps on phone/WhatsApp/email links, a form started, scroll depth, and the ids of the sections seen.
The server maps each id to its page and type from the published content (`services`, `services-2`
for a repeated one), so a client can't invent labels; only `click`, `scroll` and `form` events are
accepted from it. Lead forms stay plain HTML.

## Sections seen, and clicks in them


A section counts once per page view when at least half of it (or half the screen, for a tall one) has
been on screen for half a second (`IntersectionObserver`, shared code in `script-parts.ts`). External
sites name them: `data-sc-section="pricing"` on the element, or on the script tag
`data-track-sections="#pricing=pricing; .faq-block=faq"`. Stored as `section` events labelled
`<page path>#<name>` (rebuilt from its parts, 100 characters). Reports → "Sections visitors saw": per
page, views, clicks and the share of that page's views. **Every section of the published site is listed, in page order, even with no views yet** (`sectionMap` in `modules/sites/published-content.ts`, shared with the script's server side), then any others that were counted. A tap or click inside a section counts as a `sclick` for it: on SimpleCatch sites the script sends the id of the section the tap was in (`clk`), on other websites the innermost section the owner named. Taps outside any section (the nav, the footer) count for none.

## Counting chosen buttons (external sites)

Not every button: the owner names the ones that matter, so the report stays short and no page text is
read. Two ways, both in the Site card: `data-sc-click="book-appointment"` on the element (a click on
anything inside it counts, nested ones count each), or on the script tag
`data-track="#book-btn=book-appointment; .buy-now=buy"` (selector=name pairs, `;`-separated, split at the
last `=`) for builders that can't add attributes. An invalid selector is ignored. The name is cleaned
(`normalizeCtaName`: one line, no control characters, 40 characters; empty is dropped). Reports show
"Clicks on chosen buttons". Not for SimpleCatch's own sites (no script) and not for buttons inside a
third-party widget's iframe.

## Server

- Same key, CORS and CSRF rules as the lead and visit endpoints; its own per-IP limit
  (`EMBED_EVENT_RATE_LIMIT_MAX`); bots (user agent) ignored.
- `event_counts` (business × local day × kind × label → count). Labels are checked per kind
  (`eventLabel`): only a page path is free text, normalized to 100 characters. At most 500 distinct
  rows per business per day.
- Reports: `behavior` in the summary: page views, top 10 pages, devices, taps, scroll, forms started,
  and landing pages with their visits and the inquiries whose attribution landed there.
- A direct visitor's lead from another website now keeps its attribution (`source: direct`, with the
  landing page) so landing pages can show their inquiries. Reports show `direct` as unknown (like
  leads without a source) and the leads filter "unknown" includes it.

## Screens

Reports → "What visitors do on your website": six facts (page views, taps on phone/WhatsApp/email,
forms started, scrolled to the end and to the middle), most viewed pages, devices, and a landing-page
table ("4 of 40 (10%)"). Before any data: how to add the script.

## Limits (said plainly)

Approximate (ad blockers, uncounted bots, a closed tab before the scroll beacon); no unique people,
no journeys, no "returning visitor"; only websites with the script, not SimpleCatch's own sites (they
run no JavaScript by design); the number of forms started minus sent ones is a guide, not a funnel.

## Not in this version

Session recordings and heat maps (use a dedicated tool if wanted), a visitor id, per-page scroll,
custom events, per-page conversion beyond the landing page.

## Acceptance criteria

1. A session on `/sale/` from a phone: page, landing, device and, on leaving, scroll are counted; a
   tap on a phone link and a form started are counted once each.
2. Unknown labels (a device `toaster`, a scroll `75`) store nothing; a long path is cut; bots, wrong
   keys and garbage store nothing; another business sees none of it.
3. The landing-page table shows each page's visits and the inquiries that landed there (a direct
   visitor included), with the conversion as "x of y".
4. Hebrew and English; tenant isolation as everywhere.
