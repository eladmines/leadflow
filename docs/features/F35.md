## User story and value

As an owner or employee, when I send a quote or book an appointment, SimpleCatch writes the
follow-up down for me ("call back about quote #12" two days later, "confirm the appointment" the day
before), and closes it by itself when the customer answers or the appointment is cancelled. Any task
can point at the quote or appointment it is about, and the quote and appointment show their tasks.
On the lead page I also see the same customer's other leads.

## What the decisions say (D-213, D-212) and how D-214 / D-215 / D-216 make them exact (all Accepted)

| --------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------- |
| A task may point at one quote **or** one appointment of the same business   | Composite FKs, link column cleared on delete, checked at commit                                             |
| …and the same lead when the task has a lead                                 | With a subject the task's lead **is** the subject's lead (taken when omitted)                               |

| Quote sent → "לחזור לגבי הצעה #N", 2 days later, lead owner (or the sender) | **09:00** on the 2nd calendar day, Fri/Sat → Sunday; one open follow-up **per lead**; follows owner changes |
| Quote accepted/rejected → its open follow-up closes                         | Both the team's decision and the customer's link                                                            |
| Appointment booked → "לאשר את התור" due the day before                      | 09:00 the day before (weekend rule), or now; none for same-day; the D-152 notice **is** the task            |

| Each automation can be switched off per business                            | Default on, existing businesses too; `automations.manage` (owner + manager); Automations page               |
| Only system-created tasks close themselves                                  | `autoKind` marker; a person changing the subject turns it into a person's task                              |
| Related leads: the contact's other leads (stage, date, value)               | Member's visibility, newest first, max 10                                                                   |

## Scope

- Task ⇄ quote / appointment link (manual and automatic), shown on tasks, quotes, appointments.
- Two automatic follow-ups with their per-business switches.
- `relatedLeads` on the lead detail response.

**Out of scope:** task-to-task links or dependencies (D-213), linking a task to several subjects,
other F19 automations, holidays (only the Friday/Saturday rule of D-216), the business's opening
hours, a backfill of tasks for quotes sent or appointments booked before the release.

## Data model (migration `0006_task_subjects`, applied and reversed on the local and test DBs)

`tasks`

| Column           | Type          | Notes                                                                                      |
| ---------------- | ------------- | ------------------------------------------------------------------------------------------ |
| `quote_id`       | `uuid` null   | FK `(business_id, quote_id)` → `quotes (business_id, id)`, `ON DELETE SET NULL (quote_id)` |
| `appointment_id` | `uuid` null   | FK `(business_id, appointment_id)` → `appointments (business_id, id)`, same action         |
| `auto_kind`      | `varchar(32)` | null, `quote_followup` or `appointment_confirm` (check)                                    |

- `tasks_one_subject_check`: `quote_id IS NULL OR appointment_id IS NULL`.
- Both FKs are `DEFERRABLE INITIALLY DEFERRED` (Postgres re-checks a key when a row inserted in the
  same transaction is updated; deleting a lead clears `lead_id` before the cascaded quote's
  `SET NULL` runs). The service checks every link **before** writing; the FK is the backstop and a
  cross-business link fails at commit.
- Indexes: `(business_id, quote_id)` and `(business_id, appointment_id)`, partial on not null;
  **unique** `tasks_open_auto_quote_key (quote_id)` and `tasks_open_auto_appointment_key
(appointment_id)` where `auto_kind IS NOT NULL AND status = 'OPEN'` (one open automatic task per
  subject; use `ON CONFLICT DO NOTHING` / catch the unique violation instead of check-then-insert).
- New unique indexes `quotes_business_id_id_key`, `appointments_business_id_id_key` (FK targets;
  can't fail, `id` is already unique).
- No check ties `auto_kind` to a subject: a deleted subject leaves the link NULL and the task lives.

`businesses`: `task_auto_quote_followup boolean NOT NULL DEFAULT true`,
`task_auto_appointment_confirm boolean NOT NULL DEFAULT true`. Adding a column with a constant
default fills every existing row, so existing businesses start **on** (D-216 (5); verified on the
local DB: 5,168 of 5,168 businesses on).

`app/db/models.py` is updated: the columns, constraints, indexes, and read-only (`viewonly`)
relationships `Task.quote` / `Task.appointment` for eager loading. Set `quote_id` / `appointment_id`
directly.

### Linking rules (manual tasks)

- `quoteId`: a quote with `business_id = ctx.business_id` that the member may see (quotes follow
  lead visibility: employees only quotes on leads assigned to them). `appointmentId`: an appointment
  of the business the member may see (employees: appointments they are the staff of). Anything else
  → 400 on that field. Same message for "doesn't exist" and "not yours".
- With a subject, the task's lead is the subject's lead: `leadId` omitted or null → set to it; a
  different `leadId` → 400 `subjectOtherLead` (field `leadId`). An appointment without a lead +
  a task `leadId` → same error. On PATCH, changing `leadId` while a subject stays → 400 unless the
  same request unlinks the subject.
- PATCH setting `quoteId` clears `appointment_id` and vice versa (the stored task never has both).
- PATCH that changes or removes the subject of an automatic task sets `auto_kind = NULL`.
- PATCH `status: OPEN` on an automatic task when another open automatic task already exists for the
  same subject: the reopened task's `auto_kind` becomes NULL (no 409).
- Read: `subject` is built from the linked quote's `number`/`status` or the appointment's
  `starts_at`/`status`, always for the task's own business.

### Automatic follow-ups (D-214)

Each trigger runs **in the same transaction** as the change that causes it and only when the
business's switch is on at that moment. Titles use `autoTaskTitles[business.language]` (he/en);
`remind = true`; `created_by_id = NULL`; a `task.created` history entry on the lead with
`data.auto = <kind>` (actor: the member who triggered it, null for customer actions).

### Due times (D-214 + D-216; mirror exactly)

All dates are calendar dates in the business's time zone (`businesses.timezone`); "09:00" is wall
clock there (DST-safe through `zonedTimeToUtc`). Weekend = Friday or Saturday.

**`quoteFollowUpDueAt(sentAt, tz)`**

1. `day = localDate(sentAt) + 2 days`.
2. If `day` is Friday → `day + 2`; Saturday → `day + 1` (the following Sunday).
3. Due = `day` at 09:00. (No "now" fallback: always in the future.)

Sun → Tue, Mon → Wed, Tue → Thu, **Wed → Sun**, **Thu → Sun**, Fri → Sun, Sat → Mon.

**`appointmentConfirmDueAt(startsAt, now, tz)`**

1. If `localDate(startsAt) <= localDate(now)` → `null` (no task at booking time).
2. `dayBefore = localDate(startsAt) - 1`; candidate = `dayBefore` 09:00.
3. If `dayBefore` is Friday or Saturday: candidate = the following **Sunday 09:00** if that is
   strictly before `startsAt`; otherwise the preceding **Thursday 09:00**.
4. If candidate `<= now` → `now`; else candidate.

| Appointment                | Due                                             |
| -------------------------- | ----------------------------------------------- |
| Monday                     | Sunday 09:00                                    |
| Tuesday–Friday             | the day before, 09:00                           |
| Saturday                   | Thursday 09:00 (Sunday would be after it)       |
| Sunday, after 09:00        | Sunday 09:00 (same day, before the appointment) |
| Sunday, at or before 09:00 | Thursday 09:00                                  |
| any, when that has passed  | now (e.g. booked Friday for Saturday evening)   |

Reschedule: `appointmentConfirmDueAt(newStart, now, tz) ?? now`. (Interpretation of D-216 (1): a
literal "move to Sunday" would put the confirm task after a Saturday appointment, so in that case it
moves back to Thursday. Flagged to the orchestrator.)

**Quote follow-up (`quote_followup`)**

| Event                                                             | Effect                                                                                                                                                                                                |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Quote sent (`POST /quotes/:id/send`), switch on                   | No open `quote_followup` on the lead → create: due `quoteFollowUpDueAt(sent_at, tz)`, assignee = lead owner if an active member, else the sender, `lead_id` = quote's lead, `quote_id` = the quote.   |
| Same quote re-sent                                                | Its open follow-up: due recomputed from the new `sent_at`, `reminder_sent_at = NULL`. No second task.                                                                                                 |
| Another quote of the same lead sent (a revision)                  | The lead's open follow-up is **re-pointed**: `quote_id` = new quote, title = new number if the title is still the system's text for the old number, due recomputed, reminder re-armed. Assignee kept. |
| Quote accepted / rejected (team `POST …/status` or customer link) | Open `quote_followup` with that `quote_id` → closed.                                                                                                                                                  |
| Lead owner changed (`PATCH /leads/:id` `ownerId`, D-216 (3))      | Open `quote_followup` on the lead → assignee = the new owner (if an active member). Owner removed (`null`) → unchanged. Due and reminder unchanged. Runs even with the switch off.                    |
| Quote duplicated                                                  | Nothing (a draft).                                                                                                                                                                                    |
| Switch off                                                        | No new or re-pointed follow-ups; closing still happens.                                                                                                                                               |

Serialise per lead (e.g. `pg_advisory_xact_lock(hashtext('taskauto:' || lead_id))`) before looking
up the lead's open follow-up; the unique index is the last line.

**Appointment confirm (`appointment_confirm`)**

| Event                                                                                                | Effect                                                                                                                                                                                                                                                                                              |
| ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Created by the team (`POST /appointments`, REQUESTED or CONFIRMED)                                   | `due = appointmentConfirmDueAt(starts_at, now, tz)`; `null` (today or earlier) → no task. Title `appointment_confirm()`. Assignee: staff if an active member → lead owner if active → first active OWNER (as D-152); none → no task. `lead_id` = appointment's lead (may be null). `remind = true`. |
| Customer's own booking: website request, WhatsApp booking, WhatsApp event request (the D-152 notice) | **One task, not two** (D-216 (2)), see "Booking notices" below.                                                                                                                                                                                                                                     |
| WhatsApp call-back slot (`call_back_from_whatsapp`, D-171)                                           | No task.                                                                                                                                                                                                                                                                                            |
| Reschedule (`startsAt` changed)                                                                      | Open task: `due = appointmentConfirmDueAt(new start, now, tz) ?? now`, reminder re-armed. Never creates or closes.                                                                                                                                                                                  |
| Staff changed to a member                                                                            | Open task's assignee → the new staff member.                                                                                                                                                                                                                                                        |
| Status → CANCELLED, COMPLETED or NO_SHOW (team PATCH or WhatsApp cancel, D-153)                      | Open task closed. Not reopened if the status later changes back.                                                                                                                                                                                                                                    |

**Booking notices (D-152 → D-216 (2)).** `AppointmentService._awareness_task` today adds a task due
now ("תור חדש: …", "בקשה חדשה לתור: …", "הזמנה חדשה: …", `remind = false`) for a customer's own
booking. It now gets `appointment_id` = the new appointment (pass the id in; for the website request
and the event request add the appointment first and flush). Then:

- **Switch on:** that task **is** the confirm task: `auto_kind = 'appointment_confirm'`, title
  `autoTaskTitles[lang].appointment_confirm(details)` with D-152's details (`name · service · when`),
  so "לאשר את התור: דנה · תספורת · יום ב׳ 7.12 10:00" / "Confirm the appointment: …"; notes as today
  (requests keep "מחכה לאישור שלכם בעמוד התורים."). Due:
  - status **REQUESTED** (website request, event request, WhatsApp booking without auto-confirm):
    **now**, `remind = false` (it needs the team's approval now; the booking already notifies);
  - status **CONFIRMED** (WhatsApp booking with auto-confirm): `appointmentConfirmDueAt(...)`,
    `remind = true`; if that is `null` (same day) → **now**, `remind = false`.
    Assignee: D-152's rule (staff → first active owner).
- **Switch off:** the notice exactly as D-152 (title "תור חדש"… , due now, `remind = false`), linked to
  the appointment, `auto_kind = NULL` (a link for display; never closed by the system).
- The cancellation notice of `cancel_from_whatsapp` ("תור בוטל: …") stays a D-152 notice
  (`auto_kind = NULL`), linked to the appointment; the open confirm task is closed in the same
  transaction.
- The call-back slot (D-171) has no notice from this code and gets no task.

**Closing** = `status DONE`, `completed_at = now`, a `task.completed` history entry with
`data.auto = true`, actor null. Only rows with `auto_kind IS NOT NULL` are ever closed.

**Lead deletion** (`LeadService.remove`): delete `tasks` where `business_id = ctx.business_id AND
lead_id = :lead AND auto_kind IS NOT NULL` **before** deleting the lead. A person's tasks keep F10's
behaviour (kept, unlinked); their quote link clears by the FK.

### Related leads (D-215)

`relatedLeads` in `GET /leads/:id`: leads with the same `contact_id`, `id <> :lead`, filtered by the
member's lead visibility (`LeadService._visible`), `ORDER BY created_at DESC, id DESC LIMIT 10`;
values from `lead_values(...)` (one query for the batch). `[]` when none.

## Edge cases

- Employee links a task to a quote on someone else's lead, or to a manager's appointment → 400.
- Task in business A with `quoteId` of business B → 400 (service); a direct DB write fails at commit.
- Quote re-sent five times → one open follow-up, due from the last send.
- Customer accepts at the same moment the team re-sends → one of them wins on the quote; if it ends
  accepted the follow-up is closed (the close runs after the status update in its transaction).
- A person ticks the follow-up done, then the quote is re-sent → a new follow-up is created (none open).
- A person reopens an old automatic follow-up while a newer one is open → it becomes a person's task.
- Lead owner is a removed member → follow-up goes to the sender.
- Lead reassigned from Dana to Avi → the open automatic follow-up moves to Avi; a person's task stays
  with Dana; a follow-up a person re-linked (now `auto_kind` null) stays too.
- Quote sent Thursday → follow-up Sunday 09:00; appointment Saturday → confirm Thursday 09:00.
- WhatsApp booking for next Tuesday, auto-confirm on → one task "לאשר את התור: …" due Monday 09:00,
  not a "תור חדש" task plus a second one.
- Appointment booked at 20:00 for 08:00 tomorrow → due now. Booked for later today → no task.
- Appointment rescheduled to today → task due now (stays open; a person decides).
- Appointment without a lead (customer by name + phone) → task with no lead; visible on the
  appointment and the assignee's task list.
- Draft quote deleted with a person's task linked → the task stays, `subject` null.
- Business time zone not Israel, DST change between send and due → helpers handle it (tests).
- Switch turned off then on → only events after it is on create tasks; no catch-up.

## Acceptance criteria

- [ ] A task can be linked to one quote or one appointment of the same business; both at once, another
      business's record or one the member can't see is refused with a Hebrew message.
- [ ] A linked task shows "על הצעה #N" / "על התור ב-…" and opens it; the quote and the appointment
      list their tasks (employees: only their own).
- [ ] Sending a quote creates "לחזור לגבי הצעה #N" due at 09:00 two days later (business time zone;
      Friday/Saturday → Sunday 09:00), assigned to the lead's owner (or the sender); re-sending or
      sending a revision never leaves two open follow-ups on the lead; changing the lead's owner moves
      the open follow-up to the new owner.
- [ ] Accepting or rejecting the quote (team or customer) closes its open follow-up; a person's task
      on the same quote stays open.
- [ ] Booking an appointment creates "לאשר את התור" due at 09:00 the day before (weekend rule, or
      now); none for a same-day appointment or a WhatsApp call-back; a reschedule moves it.
- [ ] A customer's own booking (website / WhatsApp) creates one task, linked to the appointment, not
      a notice plus a confirm task.
- [ ] Cancelling (or completing / no-show) the appointment closes its open automatic task.
- [ ] Both automations are on for new and existing businesses; each can be switched off by an owner
      or manager; off = no new tasks.
- [ ] Deleting a lead removes its automatic tasks.
- [ ] The lead page shows the contact's other leads (stage, date, value), newest first, max 10, only
      those the member may see.
- [ ] Cross-tenant walker green; `pnpm lint typecheck test build e2e` and `pytest` green.
