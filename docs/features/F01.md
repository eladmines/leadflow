## User story and value

As a business owner, I can create an account and sign in securely, so that only I (and people I
invite later) can reach my business data. Every other feature depends on it.

## Scope

Register, login, logout, current user, soft email verification (D-002), resend verification,
forgot/reset password, session management, rate limits, CSRF guard, auth audit events.

## Exclusions

Phone/SMS verification (D-015), social login, MFA, invites (F09), account deletion (F14).

## Database changes

- `users`: id, email (unique, stored lowercased), password_hash, full_name, email_verified_at, status (ACTIVE/BLOCKED), timestamps.
- `sessions`: id, user_id, token_hash (unique), expires_at, last_seen_at, ip, user_agent, revoked_at, created_at.
- `auth_tokens`: id, user_id, type (EMAIL_VERIFY/PASSWORD_RESET), token_hash (unique), expires_at, used_at, created_at.
- `audit_logs`: id, business_id (nullable), actor_user_id (nullable), action, entity_type, entity_id, metadata (jsonb), created_at.

## API contracts (draft; the Architect finalises them in `packages/shared`)

| Method | Path                                  | Body                                   | Result                                                        |
| ------ | ------------------------------------- | -------------------------------------- | ------------------------------------------------------------- |
| POST   | `/api/v1/auth/register`               | fullName, email, password, acceptTerms | 201 user; sets the session cookie; sends a verification email |
| POST   | `/api/v1/auth/login`                  | email, password                        | 200 user; sets the cookie · 401 generic message               |
| POST   | `/api/v1/auth/logout`                 | —                                      | 204; revokes the session, clears the cookie                   |
| GET    | `/api/v1/auth/me`                     | —                                      | 200 { user } · 401                                            |
| POST   | `/api/v1/auth/verify-email`           | token                                  | 200 · 400 invalid or expired                                  |
| POST   | `/api/v1/auth/resend-verification`    | — (authenticated)                      | 204 (rate limited)                                            |
| POST   | `/api/v1/auth/password-reset/request` | email                                  | 204 always (no account enumeration)                           |
| POST   | `/api/v1/auth/password-reset/confirm` | token, newPassword                     | 204; revokes all sessions                                     |

## Backend tasks

1. Prisma models + migration.
2. `lib/crypto.ts`: argon2id hash/verify, random token, sha256.
3. Session plugin (cookie → `req.auth`), `requireAuth`, sliding expiry.
4. CSRF guard (Origin allowlist + `X-Requested-With`), CORS allowlist for prod sub-domains.
5. Rate limits on register, login and reset (configurable for tests).
6. `integrations/email`: `EmailSender` interface, SMTP adapter (Mailpit), in-memory test adapter, Hebrew templates.
7. Auth service and routes; audit events (register, login success/failure, password reset).
8. Extend logger redaction; integration tests.

## Frontend tasks

1. Routes and auth guard (`useMe`), redirect logic.
2. Screens: register, login, forgot password, reset password, verify-email landing.
3. Shared Zod schemas + react-hook-form; server field errors mapped inline.
4. Unverified-email banner component (used by F03), with resend.
5. Component tests for the forms.

## Tests

- Duplicate email → 409 with a field error. Weak password → 400.
- Wrong password and unknown email give the same message and status.
- Expired, revoked and tampered sessions → 401. Logout revokes server-side.
- Verify and reset tokens are single-use and expire.
- A password reset revokes all sessions.
- Rate limit → 429. POST without an allowed Origin or `X-Requested-With` → 403.
- Logs contain no password, token or cookie (assert on captured log output).

## Acceptance criteria

- [ ] A new user registers in Hebrew UI, is signed in, and the verification email arrives in Mailpit.
- [ ] The verification banner disappears after clicking the email link.
- [ ] Forgot → email → reset → login works end to end; old sessions are invalid.
- [ ] Refreshing the browser keeps the user signed in; logout signs out on the server.
- [ ] No secret, token or password appears in logs or API responses.
