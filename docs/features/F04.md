## User story and value

As an owner without technical skills, I pick a template, edit ready-made sections and
branding, and preview on desktop and phone, all without changing my live site.

## Scope

- One site per business in the MVP (Basic tier); pages (home + optional extra pages per template).
- Sections: Hero, About, Services, Price list (basic), Testimonials, Gallery, FAQ, Contact
  (with form placeholder for F07), Map, CTA. Edit text, image refs, buttons; reorder;
  show/hide.
- Global theme: colours, font, logo ref, navigation, footer.
- Autosave with a saving/saved/error indicator; local fallback if a save fails (PRD §18 step 3).
- Changing template warns about incompatible sections and never deletes content silently.
- Preview in desktop and mobile frames, using the same `renderPage()` as publishing.
- Per-page SEO title/description; image alt text.

## Exclusions

Free-form drag-and-drop, blog, store, custom code (doc 09); publishing (F06); uploads (F05: until
then image fields accept existing asset refs only); custom domains (F11).

## Database changes (draft)

`sites` (business_id, subdomain unique nullable until publish, status DRAFT/PUBLISHED/SUSPENDED,
template_key, theme jsonb, published_version_id) · `pages` (business_id, site_id, slug, title,
seo jsonb, sort, status) · `page_drafts` (business_id, page_id, sections jsonb, revision for
optimistic locking, updated_at).

## API contracts (draft)

`GET/POST /businesses/:id/site` · `GET/PATCH /businesses/:id/site/theme` ·
`GET/POST /businesses/:id/site/pages` · `GET/PUT /businesses/:id/site/pages/:pageId/draft`
(with revision; 409 on a stale revision) · `POST /businesses/:id/site/template` (with a
`confirmIncompatible` flag) · `GET /businesses/:id/site/preview/:pageId` (rendered HTML).

## Shared contracts

Section Zod schemas + template definitions + `renderPage(theme, sections)` live in
`packages/shared` (pure, escape-safe: all user text HTML-escaped; URLs whitelisted to http/https/tel/mailto).

## Tests

Renderer snapshot and XSS tests; draft revision conflicts; template change with incompatible
sections; tenant walker covers the new routes; editor component tests; e2e edit → preview.

## What was built (MVP)

- One-page site per business (D-030); two templates pre-filled from the business profile (D-031).
- Sections: hero, about, services, price list, testimonials, FAQ, contact, call to action. Add, edit, show/hide, reorder, delete with confirmation; list items add/edit/reorder/delete.
- Design: 6 palettes, 4 Hebrew fonts (D-032). Google listing: title + description with a search-result preview.
- Autosave (800 ms debounce) with revision locking (D-033): saving / saved / failed + retry / "edited in another window" (autosave stops). Failed saves keep a local backup and offer to restore it; a pending edit is sent with `keepalive` when the page closes.
- Live preview (desktop / mobile frame) rendered by the shared `renderSitePage`, in a sandboxed iframe (D-035).
- Owner-only editing; managers and employees see a read-only preview (D-034).
- Deferred: gallery and images (F05), publishing and the public site (F06), contact form (F07), multi-page sites.

## Acceptance criteria

- [x] A new business picks a template and sees a draft site without developer help (journey 2) — `site.test.tsx`, `e2e/site.spec.ts`.
- [x] Edits autosave; reloading shows the latest draft; a save failure is visible and recoverable — `site.test.tsx` (backup + retry), e2e reload.
- [x] The draft never affects the live site (AC-03) — nothing is live until F06; publishing will snapshot the draft.
- [x] Preview matches the published render (same renderer); mobile has no overflow — e2e mobile check.
- [x] User-supplied text can't inject script into the preview or published HTML — `site.test.ts › escapes user text everywhere`; sandboxed iframe.
