## User story and value

As a visitor, I leave my details on the business's site. As the owner, every submission becomes
a lead with its exact source, and I'm notified, so no inquiry is lost.

## Scope

- Contact-form section config: basic fields (name, phone, email, message + optional custom
  text fields), required consent with privacy text, success message.
- Public endpoint `POST /public/v1/sites/:siteId/forms/:formId/submissions`: honeypot, minimum
  fill time, IP rate limit (D-013), Zod validation, consent required, idempotency key
  (double-click → one lead), works only for published sites.
- Processing: store the submission → normalise phone/email → match an existing Contact (rule:
  same phone or email in the same business → attach a new lead to that contact; never lose the
  source) → create a Lead in the first pipeline stage with source, page URL and timestamp →
  Activity → notify (in-app record + email to the owner).
- Default pipeline stages seeded per business (Hebrew, per PRD §4): New, Contacted, Quote sent, Waiting, Won, Lost.
- If the server is unavailable, the public form shows a clear error and retry; it never claims success.

## Exclusions

WhatsApp leads (F12), CAPTCHA (later), automations (F19), CSV import.

## Database changes

`forms` (business_id, site_id, config jsonb) · `form_submissions` (business_id, form_id, payload
jsonb, consent_at, source_page, ip_hash, idempotency_key unique per form, lead_id, status) ·
`contacts` (business_id, name, phone_e164, email, tags) · `pipeline_stages` (business_id,
name, sort, kind OPEN/WON/LOST) · `leads` (business_id, contact_id, stage_id, source,
source_page, owner_id, priority, expected_value, next_action_at) · `activities` (business_id,
lead_id, type, data jsonb, actor_id, created_at) · `notifications` (business_id, user_id, type, data, read_at).

## Tests

One submission → exactly one lead (AC-04); a retried idempotency key → no duplicate; honeypot or
too-fast → rejected quietly (looks like success, stored as spam or not stored); rate limit;
unpublished or foreign site/form → 404; a matching phone attaches to an existing contact; e2e
from the public site.

## Acceptance criteria

- [ ] A visitor submits the form on the live site; a lead appears with source, page and time (AC-04).
- [ ] Double submission creates one lead; bot-like submissions create none.
- [ ] The owner gets an email (Mailpit) and an in-app notification.
- [ ] Submissions to another business's or an unpublished site are rejected.
