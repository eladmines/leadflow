# F29 — Gmail conversations

Status: **Built** (first version, 2026-11-22). Decision: D-188. Builds on F27 (email), F24 (inbox), F25 (channels).

The owner's Gmail inbox feeds Conversations without forwarding rules: a customer's email becomes a
conversation and a lead; the team replies from the inbox and the reply leaves from the same Gmail.

## Scope (first version)

- **Connect** (Settings → Channels → Gmail): Google sign-in (OAuth 2.0, `access_type=offline`,
  `prompt=consent`), scopes `openid email gmail.readonly gmail.send`. The refresh token is stored sealed
  (like Meta's tokens) in `channel_connections` (`channel = gmail`, `externalId` = the Gmail address);
  a Gmail account belongs to one business. A signed state (like Facebook's) carries the business and user.
- **Sync**: every 2 minutes (in-process job), for each connected business, the inbox messages newer
  than the last sync (`syncCursor`, set to the connection time: older mail is never imported). Skipped:
  Gmail categories promotions / social / updates / forums, `List-Unsubscribe`, `Precedence: bulk|list|junk`,
  `Auto-Submitted`, no-reply senders, and the account's own address. Plain text only (HTML is reduced to
  text); quoted history is cut as in F27. Idempotent by message id.
- **Classification**: a new sender **waits** in Conversations (unclassified) until the owner marks them
  business (→ contact + `email` lead) or personal (ignored from then on). Once business, later mail joins
  their lead. Managers are notified about a new waiting sender.
- **Replies**: through the Gmail API from the connected account, threaded (`In-Reply-To`/`References`
  and Gmail's thread id), when the last message of the conversation came from Gmail. Conversations
  from the forwarding address (F27) still reply from it. No 24-hour window.
- **Disconnect**: the token is revoked at Google (best effort) and the row removed; conversations stay.
- **Adapters**: `local` (in memory, tests and development) and `cloud` (Google APIs) behind
  `apps/api/src/integrations/gmail` (CLAUDE.md rule 8).
- Not in this version: push notifications (Pub/Sub), attachments, several Gmail accounts, Outlook.

## Google setup (owner, once)

1. Google Cloud Console → a project → **APIs & Services** → enable the **Gmail API**.
2. **OAuth consent screen** (External): app name, support email, the app's domain, privacy policy and terms
   links (the same pages Meta needs). Add the two Gmail scopes. While the app is in _Testing_, add the
   Gmail addresses that will connect as **test users** (up to 100; their sign-in expires after 7 days).
3. **Credentials** → OAuth client ID (Web): authorised redirect URI
   `https://app.simplecatch.co.il/api/v1/integrations/gmail/callback`.
4. In Render → Environment: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.
5. For everyone (not only test users): publish the app and pass Google's **verification** for restricted
   scopes (a demo video, the policy pages, and a third-party security assessment, CASA). Plan weeks.

## Acceptance criteria

1. Connecting Gmail stores a sealed refresh token and shows "Connected · the address"; a forged or expired
   state goes nowhere; an address belongs to one business.
2. New mail in the inbox appears as a waiting conversation; promotions, bulk mail, auto-replies and the
   account's own mail don't; mail from before connecting is never imported; running the sync twice adds nothing.
3. Marking the sender business makes a contact and an `email` lead; later mail joins it; marking personal
   ignores them.
4. A reply from the thread leaves through Gmail, threaded, and appears once.
5. Tokens are never returned or logged; tenant isolation and permissions as in F25 (only the owner connects).
